    Go back to the last working version

    When to use this: A new version broke something and you need the old one back. Time it takes: 10 minutes You need: A terminal on the server; the commit code of the last good version.

    Before you start

    • [ ] Take a backup of the current database.
    • [ ] Find the last good version's commit code: GitHub → Actions → pick the last run that worked → copy the code after the colon in the image name, or the commit code on that run.

    Going back does not undo database changes

    Each deploy may change the database's shape. Going back runs the old program on the new database shape. This usually works, but if the change removed something the old program needs, you must also restore the database from the backup taken before the bad deploy.

    Steps

    1. Open a terminal on the server and go to the CRM folder (the one with compose.yml).

    2. Set the old version and the settings (see Deploy by hand, step 2):

    export CRM_IMAGE=ghcr.io/tareqjdtours/jst-crm-backend:<old-commit-code>
    1. Download it:
    docker pull "$CRM_IMAGE"
    1. Restart on the old version:
    docker compose -f compose.yml -f compose.staging.yml down
docker compose -f compose.yml -f compose.staging.yml up -d --build

    Check it worked

    • docker compose -f compose.yml -f compose.staging.yml ps shows all boxes running.
    • Open the CRM and sign in; open a recent file.

    The next push redeploys the new code

    The server now runs the old version, but GitHub's main still holds the bad code. Ask the developer to fix or revert it before the next push, or the bad version comes back.

    If something goes wrong

    You see Do this
    Errors mention a missing column or table The database is ahead of the code. Restore the database.
    Cannot pull the old image It may have been deleted. Build it from the old commit: see "Building the image yourself" in Deploy by hand.
