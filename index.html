    JST CRM Runbook

    How to deploy, look after and fix the CRM. Written for whoever is on duty, including when the usual person is away. You do not need to be an engineer: every page is a short list of steps you can follow one at a time.

    What the CRM is made of

    Think of it as five boxes that run together on one server:

    Box What it does
    web The website staff open. It is the part you see in the browser.
    api The brain. It receives what staff do and talks to the database.
    db The database. All the files, accounts and money records live here.
    migrate A helper that updates the database's shape on every deploy, then stops. It is meant to show as "Exited".
    driver-api A separate service for the drivers' phone app.

    All five are run by a tool called Docker Compose. A volume is the folder Docker keeps data in, so the data survives when a box is restarted. The two that matter are the database volume and the backups volume.

    The golden rules

    1. Back up before any risky change. See Backups.
    2. Never delete a Docker volume. Never run docker compose down -v or docker volume prune on the server. That erases the database.
    3. Read the error before you act. Most problems are solved by the site-down page.
    4. Write down what you did, with the time, so the next person knows.
